## 1. M0 交付了什么

**一句话：链路是真的，三条硬标准兑现两条，第三条（三平台）一次都没跑过。**

五个交付物里，除①三平台可启动外，其余四项（打开文件夹 → 递归扫描 → 侧栏树 → 点击看纯文本）全部打通，且只跑在 Windows 上。

> 下表的 M1–M6 是 MVP-SCOPE 的**需求编号**，与里程碑 M0–M3 不是同一套编号。

| Must | M0 到达的位置 | 验证 |
|---|---|---|
| M1 本地知识库管理 | 打开文件夹、侧栏树、读笔记可用；记住上次、新建、重命名未做 | 机器 + 人工 |
| M2 Markdown 编辑 | 未开始（当前是 `<pre>` 只读） | — |
| M3 持久化不丢数据 | 未开始，只有读路径 | — |
| M4 大纲视图 | 未开始 | — |
| M5 全局搜索 | 未开始 | — |
| M6 基础快捷键 | 未开始 | — |

| M0 验收标准 | 结果 | 怎么验的 |
|---|---|---|
| 1000 篇 ≤ 500ms | 954 篇 / 13ms（bench，真实文件系统），端到端 22ms | 机器 |
| 中文 / emoji 不崩 | 33 个用例（Windows；另有 1 条 Unix-only）覆盖 CJK、emoji、ZWJ、非 UTF-8、路径穿越 | 机器 |
| 三平台 CI 全绿 | **未达成**：只跑过 Windows，仓库没有 CI 配置 | 未验 |

两个缺口：

1. **"跨平台"没被撞碎，只是没撞。** MVP-SCOPE 说 M0 的唯一目的是把跨平台不确定性在第一周撞碎，而 macOS / Linux 一次都没启动过。这是 M0 唯一的红灯。
2. **验证方式不对称。** 机器验 = cargo test / bench / tsc / lint / build 能重复跑出来的；人工验 = 无 GUI 下用 CDP 读真实 DOM 与 IPC 返回值，一次性观察、无回归保护。前端 IPC 重构后 `vaultScan` / `noteRead` 只做了静态验证，运行时没再点过。另外 9 处用例依赖符号链接 / junction 能建出来，环境不满足就打印一行 `return`，而 cargo test 不显示通过用例的 stdout——"全绿"不等于"全跑过"。

## 4. M1 第一步

**先做 `note_save` 的写链路 + 可重复执行的 `kill -9` 脚本；CM6 排在后面。开工前花半天接 `tauri-specta`。**

1. **M1 唯一不可妥协的验收项是"kill -9 20 次零丢失"，不是"能打字"。** 编辑器接得再顺，写盘没验过，里程碑就是没验收。
2. **写路径的防线现在是死代码。** `resolve_for_write` 写好了、有测试，但没有任何命令调用它。第一个写文件的人若图省事用 `root.join()`，边界就白建了。
3. **先接编辑器会制造假象。** CM6 一接上人就开始打字，此时没有保存，每分钟都在产生"看起来能写、其实会丢"的错觉；反过来，先有保存，60fps / 16ms 才有真实文档可测。

`tauri-specta` 放最前面不是洁癖：`note_save` 的类型只该写一次；而且 `app_ping` 在 Rust 侧还是无类型的 JSON，单边契约已有一个，M1 再加三个命令就会变成四个。

顺序：**specta（半天）→ `note_save` 原子写 → `kill -9` 脚本 → CM6 接入**。

M1 结束时只回答一个问题：**"用户现在断电，丢多少？"** 答案必须是"最多 1.5 秒"。
